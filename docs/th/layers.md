# ชั้นข้อมูล

ชั้นข้อมูล (Layers) เป็นความสามารถเสริมของมุมมอง **Map** ตามปกติ เปิดเครื่องมือ
Layers ที่มุมล่างซ้ายของแผนที่ ระบบไม่มีหน้าชั้นข้อมูลแยกต่างหาก และ Coverage
ยังคงอธิบายเฉพาะ Tile Archive เท่านั้น

## โมเดลชั้นข้อมูลร่วม

ปลั๊กอินชั้นข้อมูลสร้างบนเรขาคณิตจุด เส้น และพื้นที่ซึ่งใช้ร่วมกัน
ระบบจัดเก็บเรขาคณิตและคุณสมบัติของ Feature แยกจากสี ความกว้าง รูปแบบ marker
ความทึบ และตัวเลือกการนำเสนออื่น ชั้นข้อมูลอาจใช้เพื่อการตกแต่งเท่านั้น โดยสร้าง
เนื้อหาที่มองเห็นจากแผนที่ปัจจุบันโดยไม่จัดเก็บ Features หรือ Assets ก็ได้
ปลั๊กอิน Track เชี่ยวชาญข้อมูลเส้นและเก็บเวลาและระดับความสูงของแต่ละจุดยอดได้
ส่วนปลั๊กอิน Photo เชี่ยวชาญข้อมูลจุด พื้นฐานนี้ยังรองรับ POI เส้นทาง และภูมิภาค
ในปลั๊กอินอนาคตได้

ใช้ **Add layer** และตัวเลือกไอคอนเพื่อสร้างชั้นข้อมูล Track, Photos หรือ Decorations
ชื่อเป็นตัวเลือก หากเว้นว่างระบบจะใช้ชื่อพร้อมหมายเลขว่างถัดไป เช่น `Track 1`
หลังสร้าง ระบบจะเลือก Layer ใหม่ใน tree dropdown เปิดตัวแก้ไขเพียงรายการเดียว
และโฟกัสการควบคุมนำเข้าหรือสแกน checkbox ใน dropdown เปลี่ยนการมองเห็นโดยไม่เปลี่ยน
ตัวแก้ไขที่เลือก เมื่อเปิดเครื่องมือ Layers โดยไม่ระบุเป้าหมาย ระบบจะคืน Layer ล่าสุด
ที่จัดเก็บไว้ในเบราว์เซอร์ หรือเลือก Layer แรกที่มองเห็นหากไม่มีค่านั้น slider
**Opacity** ทั่วไปใช้กับ Layer ทั้งหมด ทั้งบนแผนที่แบบโต้ตอบและในการส่งออก

Layers รวมเป็น overlay stack ชุดเดียวทั่วทั้งระบบโดยไม่ขึ้นกับชุดแผนที่
การเปลี่ยนชุดแผนที่จะเปลี่ยนเฉพาะแผนที่ฐาน แล้วนำ overlays เดิมกลับมาติดตั้ง
ตามลำดับ การมองเห็น ความทึบ ช่วง Zoom และการตั้งค่าเดิม หากปลั๊กอินที่ต้องใช้
ซึ่งติดตั้งในขั้น build หายไปหรือเข้ากันไม่ได้ ระบบจะปิดชั้นข้อมูลและรายงาน
การวินิจฉัยโดยไม่ลบข้อมูลที่จัดเก็บไว้ ไม่สามารถติดตั้งปลั๊กอินผ่านเบราว์เซอร์
หรือ API ได้

ลำดับชั้นระดับแรกมาจากหมวดหมู่ปลั๊กอิน เช่น **Tracks**, **Photos** หรือ
**Decorations** ใช้ `/` ในชื่อ Layer เพื่อสร้างโฟลเดอร์ระดับลึกขึ้น:
`Trips/2026/Alps` จะปรากฏใต้ `Tracks > Trips > 2026` การเปลี่ยนชื่อ Layer
จะเปลี่ยนพาธนี้ โดยไม่มีการสร้างระเบียนโฟลเดอร์แยกต่างหาก สามารถยุบหมวดหมู่
และโฟลเดอร์ที่สร้างขึ้นแต่ละระดับได้อย่างอิสระ ระบบจะเก็บค่าการแสดงผลเหล่านี้
ไว้ในเบราว์เซอร์

## การตกแต่ง Tile Grid

เพื่อเข้าถึงอย่างรวดเร็ว ให้เปิด **Show Tile Grid** ใน **Display Options**
หรือ context menu ของมุมมอง **Map** *maptoy* จะใช้ Tile Grid Layer ชื่อ
`Default Grid` พร้อมการตั้งค่าปัจจุบันซ้ำ หรือสร้างด้วยค่าเริ่มต้นหากยังไม่มี
เมื่อปิดตัวเลือก ระบบจะซ่อน Layer โดยไม่ลบออก คุณสามารถแก้ไข ซ่อน หรือลบ
`Default Grid` ได้เหมือน Layer อื่นในแผง Layers ตัวเลือกด่วนจะเปลี่ยนตาม
การมองเห็นของ Layer นี้และปิดเป็นค่าเริ่มต้น

สร้างชั้นข้อมูล **Decorations** เพื่อแสดงขอบเขตของไทล์ XYZ ที่แผนที่ฐานปัจจุบันใช้
ไทล์ที่มองเห็นแต่ละรายการจะมีป้าย `z/x/y` ตาม source Zoom จำนวนเต็มจริงและ
พิกัด X แบบ canonical ป้ายจึงยังตรงกับไทล์ที่ขอเมื่อ map Zoom เป็นขั้นละหนึ่งในสี่
เมื่อใช้ไทล์ขนาด 256 หรือ 512 พิกเซล และเมื่อแผนที่วนข้ามเส้นแอนติเมริเดียน

Layer เดียวกันสามารถแสดงมาตราส่วนเมตริกผ่านจุดกึ่งกลางภาพของไทล์ที่มองเห็นแต่ละ
รายการ โดยวางป้าย `z/x/y` ไว้ด้านบน แถบแต่ละรายการรักษาความกว้างที่กำหนดไว้
25–100 เปอร์เซ็นต์ของไทล์ ขณะที่ป้ายอธิบายระยะทางท้องถิ่น ณ ละติจูดและ source Zoom
นั้นโดยตรง ระบบแสดงระยะกึ่งกลางที่อ่านง่ายสามค่าและปลายทางปัดเศษที่แน่นอน
แต่ละช่วงหลักแบ่งเป็นส่วนสีดำและขาวสลับกันสิบส่วน และส่วนสุดท้ายตามสัดส่วนแทน
ระยะที่เหลือ สามารถเปิดปิดกริด ป้าย และมาตราส่วนแยกจากกัน ตัวแก้ไข Layer ยังควบคุม
สีเส้น ข้อความ และพื้นหลังป้าย รวมถึงความโปร่งใสแยกแต่ละรายการ ส่วนการควบคุม Layer
ร่วมยังคงกำหนดความทึบและขีดจำกัด Zoom

Tile Grid จัดเก็บเฉพาะการตั้งค่าที่ผ่านการตรวจสอบและค่าทั่วไปของ Layer
โดยไม่สร้าง Asset ที่นำเข้า Job เบื้องหลัง หรือ Feature บนแผนที่แบบถาวร
เมื่อเปลี่ยนชุดแผนที่ ระบบจะคงอินสแตนซ์ Layer และคำนวณการตกแต่งใหม่สำหรับ
แผนที่ฐานใหม่

## นำเข้าแทร็ก

สร้าง Track Layer แล้วเลือกคำสั่ง **Import track…** ที่เน้นไว้ หลังนำเข้าสำเร็จ
คำสั่งรองจะเปลี่ยนชื่อเป็น **Replace track…** เพราะไฟล์ใหม่จะแทนที่เรขาคณิต Track
ที่ปรับรูปแบบแล้ว ทั้งสองคำสั่งรองรับ GPX และ GeoJSON ไฟล์อัปโหลดจะได้รับ Asset ID
ที่ระบบสร้างและเก็บไว้ใต้ `MAPTOY_STORAGE_DATA_DIR/layer-assets` ชื่อไฟล์เดิม
จากไคลเอนต์เป็นเพียง metadata ระบบจะปรับ GPX track segments และ GeoJSON Features
ชนิด LineString หรือ MultiLineString ให้เป็นโมเดลเส้นร่วม และปฏิเสธ GPX DTD
กับ entity declarations ขนาดอัปโหลดจำกัดด้วย `MAPTOY_LAYERS_ASSET_MAX_BYTES`
และปลั๊กอิน Track จะตรวจสอบก่อนอัปเดต Layer

## ไดเรกทอรีภาพภายนอก

*maptoy จะไม่นำเข้าไฟล์ภาพต้นฉบับมาไว้ในไดเรกทอรีข้อมูลของระบบ* กำหนดไดเรกทอรี
บนโฮสต์ที่มีอยู่แล้วในไฟล์ `.env` ของ repository:

```dotenv
MAPTOY_PHOTOS_DIR=/srv/photos
```

เริ่ม *maptoy* ตามปกติ:

```sh
docker compose up --build
```

ไฟล์ Compose มาตรฐานจะ mount ไดเรกทอรีดังกล่าวแบบอ่านอย่างเดียวที่ `/photos`
ภายในคอนเทนเนอร์และตั้งค่าให้ *maptoy* ใช้งาน ตัวแปรจำกัดภาพมีค่าเริ่มต้นอยู่แล้ว
จึงไม่ต้องเปลี่ยนสำหรับการทดสอบครั้งแรก หลังเริ่มระบบ `GET api/photos/directory`
จะรายงาน `available: true` เมื่ออ่าน mount ได้ โดยไม่ส่งคืน absolute path ทั้งสองฝั่ง
คำขอสแกนรับเฉพาะไดเรกทอรีย่อยแบบสัมพัทธ์ที่ปรับรูปแบบแล้ว และปฏิเสธ absolute path,
parent traversal และการออกนอกขอบเขตผ่าน symbolic link

## สแกนภาพ

สร้าง Photos Layer เลือกว่าจะสแกนแบบ recursive หรือไม่ แล้วเลือก
**Scan directory…** ตัวเลือกไดเรกทอรีจะแสดงเฉพาะโฟลเดอร์ใต้ไดเรกทอรีภาพที่กำหนด
และไม่เปิดเผย absolute path เข้าไปยังไดเรกทอรีย่อยแล้วเลือก
**Scan this directory** ระบบจะปิดการเลือก root ที่กำหนดไว้โดยตรง ทำให้กำหนด
โฟลเดอร์แหล่งข้อมูลแยกให้ Photos Layer แต่ละรายการได้สะดวก Job แบบถาวรสามารถ
pause, resume หรือ cancel ได้ งานสแกนที่หยุดกลางคันจะกลับเข้าคิวหลังรีสตาร์ต
ผลสแกนโดยละเอียดยังคงแสดงจนกว่าจะปิด dialog Layers เมื่อเปิดอีกครั้ง ระบบจะแสดง
โฟลเดอร์ล่าสุดแบบสัมพัทธ์กับ `MAPTOY_PHOTOS_DIR` และจำนวน Photo ที่โหลดไว้เหนือ
คำสั่งสแกนแทน โดยคืนค่าโฟลเดอร์และตัวเลือก recursive จาก Job ล่าสุดของ Layer นั้น

การสแกนครั้งแรกจะรับเฉพาะภาพที่มีจุด GPS จาก EXIF ซึ่งครบถ้วนและถูกต้องเข้าสู่
catalog ระบบจะสร้างภาพตัวอย่าง WebP ที่หมุนตาม EXIF และไม่มี metadata พร้อมบันทึก
fingerprint จากขนาดและ mtime ของแต่ละภาพที่รับเข้า ภาพซึ่งไม่มีตำแหน่งถูกต้องจะ
ไม่ถูกจัดเก็บ และผลสแกนจะแสดงจำนวนที่ข้ามแยกต่างหาก การสแกนครั้งถัดไปจะข้ามไฟล์
ใน catalog ที่ไม่เปลี่ยนแปลงก่อนถอดรหัส ส่วนไฟล์ที่เปลี่ยนจะประมวลผลใหม่ ไฟล์ที่
ไม่มีอยู่แล้วจะมีสถานะ `missing` แต่ metadata และภาพตัวอย่างเดิมยังใช้งานได้

เบราว์เซอร์จะไม่โหลด Asset ทุกหน้าสำหรับทุก Layer ล่วงหน้า เมื่อเลือก Photo Layer
ระบบจะโหลดหน้าแรกของ catalog และ **Load more photos** จะติดตาม cursor ของเซิร์ฟเวอร์
เมื่อจำเป็น แผนที่จะโหลดหน้าตาม cursor จนครบเฉพาะ Photo Layers ที่มองเห็น เพื่อให้
catalog ที่ซ่อนไว้ไม่ทำให้การโหลด Layers ครั้งแรกช้าลง

ระบบใช้ EXIF GPS เป็นพิกัดจุดที่มีผลทันที โดยไม่มีพิกัด “detected” และ “accepted”
แยกกัน เปิด **Manage photos** เพื่อแก้ไขหรือลบจุด ตำแหน่งที่กำหนดด้วยตนเอง
หรือการตั้งใจลบจะไม่ถูกเขียนทับจากการสแกนครั้งถัดไป เฉพาะตำแหน่งที่ source ยังเป็น
`exif` เท่านั้นที่อัปเดตจากไฟล์ต้นฉบับซึ่งเปลี่ยนแปลงได้ **Center map here**
ใช้ตำแหน่งที่กรอกอยู่ในขณะนั้นโดยไม่บันทึกหรือเปลี่ยน map zoom
**Fit photos on map** ขอเฉพาะขอบเขตพิกัดขนาดย่อของ Layer และปรับจุดศูนย์กลางกับ zoom
เพื่อให้ Photo ที่มีตำแหน่งทั้งหมดพอดีแผนที่ dialog **Photo position** ยังแสดง
ค่า metadata ที่บันทึกไว้ทั้งหมดของ Photo ที่เลือก โดยไม่ขึ้นกับการตั้งค่าฟิลด์
ใน popup ของแผนที่

ระบบรวม marker ของ Photo ที่อยู่ใกล้กันเป็น cluster ตามค่าเริ่มต้น โดยใช้รัศมี
screen-pixel ที่ตั้งค่าได้ หมุด cluster จะอัปเดตหลัง pan หรือ zoom และแสดงจำนวน Photo
เมื่อคลิก cluster ระบบจะเปิดภาพรวมแบบเลื่อนได้ พร้อมภาพตัวอย่างขนาดย่อ ชื่อไฟล์
และรายละเอียด popup ที่กำหนด สำหรับ Photo ที่โหลดแบบ lazy สูงสุด 100 รายการ
โดยไม่เปลี่ยน zoom cluster ที่ใหญ่กว่านี้จะแสดงจำนวนรายการที่เหลือด้วย ปิด
**Cluster nearby photos** เพื่อแสดง marker แต่ละรายการแยกกัน เมื่อวางตัวชี้เหนือ
marker เดี่ยว ระบบจะเปิด popup ภาพตัวอย่างแทน tooltip ชื่อไฟล์ และยังคลิกได้สำหรับ
การโต้ตอบด้วย touch และ pointer popup แสดงชื่อไฟล์ พิกัดจุดในรูปแบบ DMS
และเวลาถ่ายภาพที่มีอยู่ใต้ภาพ การเลือกฟิลด์นี้กำหนดไว้ในโค้ดปัจจุบัน ผู้ผลิต
รุ่นกล้อง ISO, f-stop, shutter speed และคำบรรยาย IPTC ยังคงจัดเก็บไว้สำหรับ
ตัวเลือก popup ที่ผู้ใช้กำหนดได้ในอนาคต แต่เริ่มต้นจะซ่อนไว้

Popup เดี่ยวและ cluster จะเลือกตำแหน่งเหนือหรือใต้ marker ตามพื้นที่ว่างบนแผนที่
แก้การล้นในแนวนอน และจำกัดความสูงโดยไม่เลื่อนแผนที่อัตโนมัติเมื่อเปิด

## ข้อมูลที่จัดเก็บ

SQLite จัดเก็บอินสแตนซ์ Layer, ข้อมูล Track ที่ปรับรูปแบบแล้ว, Asset IDs,
พาธภาพแบบสัมพัทธ์, metadata ที่เลือก, fingerprints, พิกัดที่มีผล, สถานะ และ Jobs
แบบถาวร metadata ของ Photo ที่เลือกประกอบด้วยเวลาถ่าย ผู้ผลิต รุ่นกล้อง ISO,
f-stop, shutter speed เป็นวินาที และ `IPTC.caption` เมื่อมี
`MAPTOY_STORAGE_DATA_DIR` จัดเก็บไฟล์อัปโหลดที่ไม่ใช่ภาพซึ่งระบบจัดการและ
ภาพตัวอย่างที่สร้างขึ้น ไฟล์ภาพต้นฉบับยังคงอยู่เฉพาะในไดเรกทอรีภายนอกที่กำหนด
และ endpoint ภาพตัวอย่างจะไม่ส่งคืนไฟล์ต้นฉบับ

สำรองข้อมูล `MAPTOY_STORAGE_DATA_DIR` เพื่อเก็บ catalog และภาพตัวอย่าง
และสำรองไดเรกทอรีภาพภายนอกแยกต่างหากหากต้องการรักษาไฟล์ต้นฉบับ

## ขีดจำกัดภาพ

ค่าเริ่มต้นคือ 100 MiB ต่อภาพ, 100 ล้านพิกเซลหลังถอดรหัส, ขอบภาพตัวอย่าง
640 พิกเซล, batch ละ 100 รายการ, ตัวถอดรหัสพร้อมกันสองรายการ และไม่เกิน
100,000 ไฟล์ต่อการสแกน กำหนดค่าเหล่านี้ด้วย `MAPTOY_PHOTOS_MAX_FILE_BYTES`,
`MAPTOY_PHOTOS_MAX_DECODED_PIXELS`, `MAPTOY_PHOTOS_PREVIEW_MAX_EDGE`,
`MAPTOY_PHOTOS_SCAN_BATCH_SIZE`, `MAPTOY_PHOTOS_SCAN_CONCURRENCY` และ
`MAPTOY_PHOTOS_SCAN_MAX_FILES` เซิร์ฟเวอร์ยังปฏิเสธการตั้งค่าที่เกิน 256 MiB,
150 ล้านพิกเซลหลังถอดรหัส, ขอบภาพตัวอย่าง 2048 พิกเซล, batch 1,000 รายการ,
ตัวถอดรหัสสี่รายการ หรือ 250,000 ไฟล์ตั้งแต่เริ่มระบบ ค่าเริ่มต้นและเพดานเหล่านี้
อ้างอิงจาก benchmark ภาพใน Phase 5 ที่ทำซ้ำได้
