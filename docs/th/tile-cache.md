# แคชไทล์

*maptoy* จัดเก็บไทล์แรสเตอร์ที่ผ่านการตรวจสอบแล้วเป็น revision ที่แก้ไขไม่ได้
ไว้ใต้ `MAPTOY_STORAGE_DATA_DIR/tiles` ประวัติ revision และตัวชี้ไปยังรายการปัจจุบัน
อยู่ใน SQLite ส่วนไบต์ของภาพยังคงเข้าถึงได้โดยตรงในไดเรกทอรีข้อมูลบนโฮสต์

## โหมดรีเฟรช

คำขอแผนที่ตามปกติใช้โหมด `auto` ซึ่งจะส่งคืน revision ปัจจุบันจนกว่าจะเกิน
อายุสูงสุดที่กำหนดไว้ หากไทล์ล้าสมัยหรือยังไม่มี ระบบจะขอจากผู้ให้บริการ
เมื่อทำได้ *maptoy* จะส่ง `If-None-Match` หรือ `If-Modified-Since`; ข้อมูลตอบกลับ
`304` จะอัปเดตเฉพาะเวลาที่ตรวจสอบเท่านั้น

- `auto` ใช้ revision ในแคชที่ยังใหม่ และตรวจสอบเนื้อหาที่ล้าสมัย
- `force` ติดต่อผู้ให้บริการโดยไม่คำนึงถึงอายุสูงสุดที่กำหนด
- `cache-only` ไม่ติดต่อผู้ให้บริการ หากไม่มีไทล์ที่เลือก *maptoy* จะส่งคืนภาพ PNG
  `no_cache` ลายทแยงตามขนาดไทล์ที่กำหนด พร้อมพิกัด `z`, `x`, `y`
  และ `X-Maptoy-Cache: miss`

API รับโหมดผ่าน `?refresh=auto`, `?refresh=force` หรือ `?refresh=cache-only`
คำขอพร้อมกันสำหรับไทล์เชิงตรรกะที่ยังไม่แคชรายการเดียวกันจะใช้คำขอไปยัง
ผู้ให้บริการร่วมกัน ตัวเลือก **Cached Tiles Only** ในมุมมอง **Map** ใช้
`cache-only` พื้นที่ซึ่งไม่มีไทล์จึงแสดงเป็นลายแทนการสร้างทราฟฟิกไปยังผู้ให้บริการ
เซิร์ฟเวอร์แคชไบต์ของ error Tile ที่สร้างขึ้นไว้ในหน่วยความจำ แต่ข้อมูลตอบกลับ HTTP
ใช้ `Cache-Control: no-store` เพื่อให้ไทล์ที่เพิ่งเพิ่มเข้า archive แทนที่ภาพชั่วคราว
ได้ทันที

## เพิ่มไทล์จากภายนอก

ไคลเอนต์ API ที่เชื่อถือได้สามารถเพิ่มไทล์เชิงตรรกะหนึ่งรายการโดยไม่ติดต่อ
ผู้ให้บริการที่ตั้งค่าไว้:

```sh
curl --request POST \
  --header 'Content-Type: image/png' \
  --header 'X-Maptoy-Upstream-ETag: "tile-v1"' \
  --header 'X-Maptoy-Upstream-Last-Modified: Wed, 02 Sep 2026 08:00:00 GMT' \
  --data-binary '@tile.png' \
  "$MAPTOY_SERVER_URL/api/map-sets/$MAP_SET_ID/tiles/10/550/335"
```

Request body คือไฟล์ PNG, JPEG หรือ WebP ที่ไม่ผ่านการดัดแปลง endpoint นี้ไม่ใช้
multipart encoding ไฟล์ต้องถอดรหัสได้สำเร็จ media type และรูปแบบภาพจริงต้องตรงกับ
รูปแบบไทล์ที่กำหนดในชุดแผนที่ และความกว้างกับความสูงต้องเท่ากับขนาดไทล์ที่กำหนด
พิกัดต้องอยู่ภายในช่วง zoom และขอบเขต XYZ ของชุดแผนที่ ต้องเปิดความสามารถ Tile Archive
และนโยบายแคช และต้องไม่เกินทั้ง `MAPTOY_TILES_MAX_BYTES` กับขีดจำกัดพื้นที่จัดเก็บ
ของชุดแผนที่

ไคลเอนต์ที่เชื่อถือได้สามารถส่ง `ETag` และ `Last-Modified` ที่ตรวจพบจาก
upstream representation เดียวกันทุกประการผ่าน `X-Maptoy-Upstream-ETag` และ
`X-Maptoy-Upstream-Last-Modified` ได้ maptoy จะจัดเก็บ validator เหล่านี้และใช้กับ
คำขอแบบมีเงื่อนไขครั้งถัดไปไปยังผู้ให้บริการ ห้ามส่ง validator จาก URL, รูปแบบ
request header หรือ representation อื่น เพราะ validator ที่ไม่ตรงกันอาจทำให้
คำตอบ `304` ของผู้ให้บริการยืนยันไบต์ที่อัปโหลดผิดรายการ

revision ใหม่ที่แก้ไขไม่ได้จะส่งคืน `201` และ
`{ "revisionId": "...", "created": true }` หากอัปโหลดไบต์เหมือน revision ปัจจุบัน
ระบบจะส่งคืน `200` พร้อม `created: false` อัปเดตเฉพาะเวลาที่พบข้อมูล และไม่ใช้
พื้นที่จัดเก็บเพิ่ม revision ที่อัปโหลดมี origin เป็น `upload`; การอ่านแบบปกติและ
`cache-only` ในภายหลังจะส่งคืนไบต์เหล่านั้นโดยไม่ติดต่อผู้ให้บริการ ตราบใดที่
revision ยังใหม่อยู่

ข้อผิดพลาดการอัปโหลดใช้สัญญาต่อไปนี้:

- `415 TILE_MEDIA_TYPE_INVALID` เมื่อไม่มี Content-Type, ไม่รองรับ หรือไม่ตรงกับ
  ชุดแผนที่
- `400 TILE_CONTENT_INVALID` เมื่อถอดรหัสภาพไม่ได้ หรือรูปแบบจริงหรือขนาดภาพ
  ไม่ตรงกับชุดแผนที่
- `400 TILE_VALIDATOR_INVALID` เมื่อค่า upstream ETag หรือ Last-Modified ที่ระบุ
  ไม่ถูกต้องหรือยาวเกินขีดจำกัด
- `409 TILE_ARCHIVE_DISABLED` เมื่อปิดความสามารถ archive หรือนโยบายแคช
- `413 TILE_BODY_TOO_LARGE` เมื่อเกินขีดจำกัด `MAPTOY_TILES_MAX_BYTES`
  ซึ่งใช้เฉพาะ route นี้
- `507 TILE_STORAGE_LIMIT` เมื่อเกินขีดจำกัดพื้นที่จัดเก็บของชุดแผนที่

*maptoy* v1 ไม่มีระบบยืนยันตัวตนในแอปพลิเคชัน endpoint สำหรับเขียนนี้มีไว้สำหรับ
ไคลเอนต์ private ที่เชื่อถือได้เท่านั้น หากเข้าถึง *maptoy* ได้จากเครือข่ายที่
ไม่น่าเชื่อถือ reverse proxy ต้องยืนยันตัวตนและตรวจสอบสิทธิ์ ห้ามเผยแพร่ route
สำหรับอัปโหลดโดยไม่มีการป้องกันดังกล่าว ผู้ดูแลระบบยังคงมีหน้าที่ตรวจสอบว่าไบต์และ
validator ที่เพิ่มเข้ามาเป็นของแหล่งข้อมูลและ representation ที่กำหนด และได้รับ
อนุญาตให้จัดเก็บตามกฎหมาย

## Revision ที่แก้ไขไม่ได้

ไบต์ใหม่จะสร้าง revision ซึ่งระบุด้วยค่า hash แบบ SHA-256 revision ก่อนหน้าจะ
ไม่ถูกเขียนทับ หากเนื้อหาจากผู้ให้บริการเปลี่ยนจาก A เป็น B แล้วกลับเป็น A อีกครั้ง
*maptoy* จะบันทึก revision ตามเวลาสามรายการ แต่ใช้ไฟล์ A เดิมซ้ำ แต่ละ revision
ยังบันทึกด้วยว่าไบต์ที่สร้างรายการนั้นมาจาก `provider` หรือ API `upload`

ไฟล์ใช้โครงสร้างดังนี้:

```text
tiles/<map-set-id>/<z>/<x>/<y>.<content-hash>.<ext>
```

ระบบเขียนไฟล์ชั่วคราวใต้ไดเรกทอรีข้อมูลที่จัดการ และย้ายแบบ atomic หลังตรวจสอบ
content type, รูปแบบภาพจริง, ขนาดภาพ, ความสามารถในการถอดรหัส, ขนาดข้อมูล และ hash
เรียบร้อยแล้วเท่านั้น

## เลือกสถานะแคช

URL ไทล์เริ่มต้นส่งคืน revision ปัจจุบัน สามารถเลือกข้อมูลย้อนหลังแบบอ่านอย่างเดียว
ได้ด้วย query parameter เพียงหนึ่งรายการต่อไปนี้:

- `snapshot=<snapshot-id>` เลือก revision ที่บันทึกไว้ในสแนปช็อตซึ่งแก้ไขไม่ได้
- `asOf=<ISO-8601 timestamp>` เลือก revision ที่ระบบรู้จัก ณ เวลานั้น
- `revision=<tile-revision-id>` เลือก revision ที่ระบุโดยตรงหนึ่งรายการ

การเลือกข้อมูลย้อนหลังจะไม่สร้างคำขอไปยังผู้ให้บริการ

## สแนปช็อตและการเปรียบเทียบ

เปิด **Tile Cache** เพื่อสร้างสแนปช็อตที่มีชื่อจาก revision ปัจจุบันทั้งหมดของ
ชุดแผนที่ สแนปช็อตไม่คัดลอกไฟล์ภาพ แต่จะเก็บข้อมูลอ้างอิงที่ป้องกันไว้อย่างชัดเจน
ทำให้การอ่านในภายหลังทำซ้ำได้

มุมมองเดียวกันสามารถเปรียบเทียบสแนปช็อตกับสถานะปัจจุบันด้วย content hash
และรายงานไทล์ที่เหมือนกัน เปลี่ยนแปลง เพิ่มเข้ามา และหายไป การลบสแนปช็อตจะลบ
เฉพาะข้อมูลอ้างอิงเหล่านั้น ไม่ใช่ Tile Revisions ตัวนับสำหรับการเปรียบเทียบจะ
รวมผลใน SQLite แทนการโหลด hash ของทุกไทล์เข้าสู่หน่วยความจำเซิร์ฟเวอร์

## แผนที่ Coverage

เปิด **Coverage** เพื่อตรวจสอบส่วนที่มีขอบเขตของ Tile Archive บนแผนที่
เลือกชุดแผนที่ source Zoom และสถานะปัจจุบัน สแนปช็อตที่แก้ไขไม่ได้ หรือเวลาแบบ
ISO-8601 แผนที่จะจำแนกพื้นที่ที่เลือกเป็น fresh, stale หรือ missing
สามารถยุบส่วนควบคุม **Cache state** เมื่อไม่ใช้งาน

เลือกเซลล์เพื่อดูจำนวน Revision ขนาดข้อมูลที่เลือก และเวลาตรวจสอบ แถบด้านข้าง
จะเลื่อนรายละเอียดเซลล์เข้ามาในมุมมอง tooltip ข้อมูล **Aggregation Grid** แสดงว่า
แต่ละเซลล์ของกริดแทน source Tiles กี่รายการ legend ยังมีตัวเลือก **Show grid**
ซึ่งบันทึกค่าไว้ เมื่อปิด ระบบจะซ่อนขอบกริดและยังเลือกเซลล์สีได้

คำขอ Coverage จำกัดอยู่ในขอบเขตภูมิศาสตร์ที่มองเห็นและไม่ส่งคืนเกิน 4,096 เซลล์
UI เริ่มต้นจะขอไม่เกิน 1,024 เซลล์ SQLite รวม metadata ของ Revision ที่จัดเก็บไว้
ก่อนส่งข้อมูลตอบกลับ เบราว์เซอร์จึงไม่ต้องรับทุกแถวของไทล์จากแคชขนาดใหญ่
จำนวนที่ขาดหายคำนวณจากช่วงพิกัด XYZ ทั้งหมดภายในขอบเขตที่ขอ ดังนั้นการตรวจสอบ
Coverage จะไม่ติดต่อผู้ให้บริการหรือสร้างรายการแคช แผนที่พื้นหลังแยกจาก query
แบบอ่านอย่างเดียวดังกล่าว โดยใช้โหมดไทล์ `auto` ตามปกติ และอาจขอ ตรวจสอบ
และแคชไทล์พื้นหลังผ่านผู้ให้บริการที่ตั้งค่าไว้

### Batch Downloads ใน Coverage

ขยาย **Download tiles** ในแถบด้านข้างของ Coverage แล้วลากสี่เหลี่ยมบนแผนที่โดยตรง
ใช้พื้นที่แผนที่ที่มองเห็นทั้งหมด หรือกรอกขอบเขต WGS84 ที่แน่นอน กด `Esc`
เพื่อยกเลิกการเลือกที่กำลังทำอยู่ `Ctrl`+คลิกบนแผนที่จะเปิดโหมดเลือกโดยไม่ใช้ปุ่ม
ในแถบด้านข้าง ส่วน `Ctrl`+ลากจะเลือกสี่เหลี่ยมทันที จากนั้นเลือก source Zoom ต่ำสุด
และสูงสุด ค่าเริ่มต้นจะดาวน์โหลดเฉพาะไทล์ที่ขาดหาย โหมดเสริมจะตรวจสอบไทล์ที่
ล้าสมัยอีกครั้งด้วย ค่าประมาณจะอัปเดตก่อนรับงานและรายงานจำนวนคำขอโดยคำนึงถึงแคช
ขนาดรับส่งเมื่อมีตัวอย่างในแคช ขีดจำกัดการเตือนและขีดจำกัดสูงสุดที่กำหนด
รวมถึงจำนวนคำขอรายวันที่เหลือ

ตรวจสอบข้อกำหนดของผู้ให้บริการผ่านลิงก์และยอมรับความรับผิดชอบอย่างชัดเจนก่อนนำ Job
เข้าคิว Job ที่กำลังทำงานยังอยู่ในแถบด้านข้างเดียวกัน พร้อมความคืบหน้า ไทล์ปัจจุบัน
pause, resume, cancel, retry และรายละเอียดข้อผิดพลาดที่จำกัดขนาด Job ที่เสร็จแล้ว
จะรวมอยู่ในประวัติแบบซ้อนซึ่งยุบได้ ขอบเขตที่เลือกยังมองเห็นได้เมื่อยุบส่วน Download
และไทล์ที่ worker กำลังทำงานจะแสดงร่วมกันเป็น overlay สีม่วงเหนือ Coverage
โดยไม่เปลี่ยนสีสถานะ ตัวเลือก **Selection** สามารถซ่อนหรือคืนขอบเขตที่เลือก
คำสั่ง **Download tiles** บนชุดแผนที่ที่รองรับแต่ละรายการจะเปิดขั้นตอนเดียวกันนี้
ใน Coverage โดยไม่มีหน้า Downloads แยกต่างหาก

## สถิติและการลบ

มุมมองจัดการจะโหลดผลรวมจากฐานข้อมูลและข้อมูลสรุปต่อ zoom โดยไม่ไล่อ่านไดเรกทอรี
ไทล์ Revision Explorer จะยังว่างจนกว่าจะร้องขอ แล้วโหลดสูงสุด 50 แถวต่อหน้า
พร้อมตัวกรอง zoom และ current/historical แบบเลือกได้ วิธีนี้ทำให้หน้าเริ่มต้นยังมี
ขอบเขตจำกัดแม้ archive มีขนาดใหญ่ ชิปสถานะสามารถแสดงตัวอย่าง revision ที่เลือก
จริงเมื่อร้องขอโดยไม่ติดต่อผู้ให้บริการ

**Check consistency** จะสแกนไดเรกทอรีที่จัดการอย่างชัดเจนและรายงานจำนวนไบต์จริง
ไฟล์ที่มีการอ้างอิงแต่หายไป และไฟล์ที่ไม่มีการอ้างอิง การสแกนไม่ได้เป็นส่วนหนึ่ง
ของการโหลดหน้าปกติและอาจใช้เวลาสำหรับแคชขนาดใหญ่ ขีดจำกัดพื้นที่จัดเก็บสามารถ
ปฏิเสธเนื้อหาใหม่ แต่จะไม่ลบประวัติโดยอัตโนมัติ

เฉพาะคำสั่งที่ผู้ใช้สั่งอย่างชัดเจนเท่านั้นที่ลบ Tile Revision ย้อนหลังได้
revision ปัจจุบันและ revision ที่สแนปช็อตอ้างอิงจะได้รับการป้องกัน ไฟล์เนื้อหา
จะถูกลบหลังข้อมูลอ้างอิง revision สุดท้ายถูกนำออกแล้วเท่านั้น

**Repair** จะใช้งานได้หลัง **Check consistency** สำเร็จใน session เบราว์เซอร์
