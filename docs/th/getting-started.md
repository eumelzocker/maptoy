# เริ่มต้นใช้งาน

*maptoy* จัดเก็บชุดแผนที่ (Map Set) แบบ XYZ และแสดงผลผ่านตัวเรนเดอร์ Leaflet
ระบบไม่ได้ตั้งค่าผู้ให้บริการไทล์สาธารณะไว้ล่วงหน้า: เปิด **Map Sets**
เพื่อเพิ่มแหล่งข้อมูล แล้วเลือกใช้งานที่ **Map** URL ของผู้ให้บริการจะอยู่ฝั่งเซิร์ฟเวอร์เท่านั้น
และเบราว์เซอร์จะขอไทล์ผ่าน URL ของ API ของ *maptoy* แบบสัมพัทธ์

## คำสั่งสำหรับพัฒนา

รัน `pnpm install` หนึ่งครั้งภายใน development shell ใช้ `pnpm start`
เพื่อ build และเริ่มแอปพลิเคชัน ส่วน `pnpm check` จะรันการจัดรูปแบบ (formatting)
การตรวจสอบโค้ด (linting) การ build การตรวจชนิดข้อมูล (type check) และการทดสอบ

เซิร์ฟเวอร์ใช้พอร์ต `4004` เป็นค่าเริ่มต้น รีเวิร์สพร็อกซีสามารถเผยแพร่แอปภายใต้
subpath ได้โดยตัด prefix นั้นออกก่อนส่งต่อคำขอ เส้นทางของแอปพลิเคชัน ทรัพยากร (assets)
HTML base ที่สร้างขึ้น และการเรียก API ยังคงอ้างอิงแบบสัมพัทธ์กับ URL ทางเข้าสาธารณะ

อ่านต่อที่ [Map Sets](docs/th/map-sets) สำหรับรายละเอียดการตั้งค่า
การอ้างอิงค่าความลับ (secret) การทดสอบผู้ให้บริการ และความปลอดภัยของเครือข่าย

## ไดเรกทอรีข้อมูลของ Docker

คัดลอก `.env.example` เป็น `.env` กำหนดไดเรกทอรีบนโฮสต์ด้วย `MAPTOY_DATA_DIR`
และสร้างไดเรกทอรีนั้นก่อนเริ่ม Compose การตั้งค่าเริ่มต้นคือ:

```sh
cp .env.example .env
mkdir -p .data/logs/api .data/logs/provider
docker compose up --build
```

Compose จะ bind-mount ไดเรกทอรีบนโฮสต์นั้นเข้ากับ `/data` ในคอนเทนเนอร์
ฐานข้อมูล SQLite จะถูกเก็บไว้ในนั้นในชื่อ `maptoy.sqlite` ส่วนไฟล์เก็บไทล์ (archive)
และไฟล์ส่งออกในอนาคตจะใช้ไดเรกทอรีเดียวกันที่ควบคุมโดยโฮสต์ *maptoy* ไม่ใช้ named หรือ
anonymous volume ที่จัดการโดย Docker สำหรับข้อมูลแอปพลิเคชันถาวร ไดเรกทอรีนี้ต้องเขียนได้โดย
UID `1000` ซึ่งเป็นผู้ใช้ non-root ที่รันคอนเทนเนอร์

SQLite schema เวอร์ชัน 4 คือ baseline สำหรับการใช้งานจริงของ *maptoy* การติดตั้งใหม่จะสร้าง
baseline นี้ก่อน แล้วจึงใช้ migration ที่มีหมายเลขกำกับทุกรายการตามลำดับ รวมถึงที่มาของ
Tile Revision ในเวอร์ชัน 5 เวอร์ชัน 1 ถึง 3 เป็น schema สำหรับการพัฒนาเท่านั้นและไม่รองรับเป็น
แหล่งอัปเกรด ไม่มีฐานข้อมูลใช้งานจริงที่เก่ากว่าเวอร์ชัน 4

`MAPTOY_MAX_TILE_BYTES` จำกัดทั้งขนาดการตอบกลับจากผู้ให้บริการและ raw body ของ route
สำหรับ seed ไทล์ ขีดจำกัดการอัปโหลดนี้เจาะจงเฉพาะ route และไม่ลดขนาดที่ยอมรับของ Map Set JSON
หรือคำขอ API อื่นที่ไม่เกี่ยวข้อง

## บันทึกทราฟฟิก

*maptoy* เก็บบันทึกการรับส่งข้อมูลฝั่ง client/API และฝั่ง backend/ผู้ให้บริการไทล์แยกจากกัน
โดยบันทึกเป็น JSON Lines Compose จะ bind-mount ไดเรกทอรีที่กำหนดด้วย
`MAPTOY_API_TRAFFIC_LOG_DIR` และ `MAPTOY_PROVIDER_TRAFFIC_LOG_DIR` ค่าเริ่มต้นของทั้งสอง
อยู่ภายใต้ `MAPTOY_DATA_DIR` แต่สามารถชี้ไปยังที่อื่นบนโฮสต์ได้ทั้งคู่ ไฟล์ที่ใช้งานอยู่มีชื่อว่า
`api-traffic.log` และ `provider-traffic.log`

`MAPTOY_TRAFFIC_LOG_MAX_BYTES` กำหนดขนาดของแต่ละไฟล์ก่อนหมุนเวียน (rotation)
`MAPTOY_TRAFFIC_LOG_MAX_FILES` กำหนดจำนวนไฟล์ทั้งหมดที่เก็บไว้ต่อประเภททราฟฟิก
รวมถึงไฟล์ที่ใช้งานอยู่ Header สำหรับการยืนยันตัวตน คุกกี้ และพารามิเตอร์ query
ที่มักเป็นความลับจะถูกปิดบัง (redact) ไดเรกทอรี log ต้องมีอยู่ก่อนเริ่ม Compose และต้องเขียนได้โดย
UID `1000` คำขอไปยัง endpoint สำหรับ liveness ที่ `api/health` จะไม่ถูกบันทึกใน API traffic log
ไม่ว่าจะมาจากที่ใด ส่วน Docker ยังคงตรวจสอบและรายงานสถานะสุขภาพของคอนเทนเนอร์ตามปกติ

Endpoint สำหรับ readiness จะตรวจสอบฐานข้อมูลและความสามารถในการเขียนต่อเนื่องของไดเรกทอรีข้อมูล
แอปพลิเคชันและไดเรกทอรี traffic log ทั้งสอง traffic log ที่ตั้งค่าไว้นอก `MAPTOY_DATA_DIR`
ไม่ถือเป็นส่วนหนึ่งของการสำรองข้อมูลแอปพลิเคชันหลัก และต้องสำรองแยกต่างหากเฉพาะเมื่อต้องการเก็บ
บันทึกการทำงานที่มีขอบเขตจำกัดเหล่านี้ไว้
