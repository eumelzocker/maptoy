Optional response header forwarding
Rules remain independent of the target server. A rule's forwardResponseHeaders object maps source response header names to request header names sent with the POST. No response headers are forwarded unless they are explicitly mapped. Only map headers whose meaning the target server understands and trusts.

Example config

Two real-world rules, forwarding to a local maptoy API:

  • MapTiler tiles (mapset name mapped to an internal map-set id via lookups)
  • OpenTopoMap tiles (no lookups, fixed target map-set).

Settings:

  • enabled (global & per rule) is optional, defaults to true.
  • logging (global) optional, defaults to false, toggles POST requests logs in browser console.
  • maxResponseBytes sets the global memory limit; blank or null disables it.
  • match: regex with named groups, e.g. (?<mapset>...).
  • target: target URL template, references named groups as ${name}.
  • lookups: optional, per rule and per named group. Maps the captured value to another value. Groups (or whole rules) without a lookup table are passed through as-is.
  • forwardResponseHeaders: optional source-response to target-request header-name mapping. Missing source headers are omitted.
  • maxResponseBytes and responseStatusCodes can override response handling per rule.
  • If multiple rules match the same URL, or a lookup entry is missing → error, no POST.
